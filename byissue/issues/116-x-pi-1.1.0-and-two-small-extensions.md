# 升级 pi 1.1.0 并收编两个个人 small-extension

## 背景

用户在 `~/.pi/agent/extensions/` 维护两个日常在用的个人扩展（源文件为用户手写、未入库）：

- `context-guard.ts`：context 窗口大于 400k 的模型在过 400k 后触发一次 compact（小窗口模型不干预）；并把 session 文件路径写进 system prompt，使 compaction 摘要丢掉的细节仍可被检索。
- `hide-direct-tools.js`：codemode `only` 模式的补丁——拦截对 direct tools 的顶层调用（嵌套调用放行），并改写 system prompt 的 <tools> 尾句与 <skills> 读法提示，使提示与 only 模式一致。

用户判断两者日常收益成立，要求收编进仓库；同时拍板仓库依赖整体升级到 pi 最新版（npm latest = 1.1.0，与用户本机运行版本一致），扩展按 1.1.0 类型原生编写。

现状：仓库 lockfile 钉在 pi 0.84.3；跨 0.85→0.99→1.0→1.1 升级，六个包 + 两个 small-extension 共约 38 个文件引用 pi 类型，typecheck 与测试需全量回归。

## 做了什么

1. **升级依赖**：六个包与两个现有 small-extension 的 peerDependencies 下限统一提到 `>=1.1.0`，`npm install` 更新 lockfile。
2. **回归修复**：全仓 typecheck + test 按 1.1.0 类型修断；pi-image-gen build + pack-smoke、pi-vendor pack dry-run 复验。
3. **收编两个扩展**（目录 `small-extensions/`，均零运行时 import、不注册 tool）：
   - `pi-context-guard/`：沿用用户逻辑与阈值 400_000（源文件注释写 300k 是漂移，以代码为准，收编时修正注释）；导出 `shouldCompact` 纯函数便于测试。
   - `pi-codemode-only/`：由 `.js` 转 `.ts`；`TOOLS_TAIL` / skills 句式正则按 1.1.0 实际 system prompt 校对；导出纯函数便于测试。
   - 各配 test + package.json（private）+ tsconfig + README。
4. **安装与文档**：install-small-extension.sh / .ps1 清单各加两行；small-extensions/README.md 与根 README 表格补行；spec 证据索引同步。

## 验证结果

- 升级依赖：8 个 package.json 下限 `>=1.1.0`，lockfile 落到 1.1.0；root `allowScripts` 对齐新版（`@google/genai@2.21.0` / `esbuild@0.28.2` / `protobufjs@7.6.6`）。
- 1.1.0 类型断点只有 pi-vision 两处：`BeforeAgentStartEvent.systemPromptOptions` 收紧为 `NormalizedBuildSystemPromptOptions`（归一化形态，9 个集合字段必填）。normalizer 未从包根导出、深路径被 exports map 禁掉，故在 `test-helpers.ts` 加 `fixtureSystemPromptOptions()` / `beforeAgentStartEvent()` 显式构造完整形状，两个 fixture 改用它。
- 全仓 `npm run typecheck --workspaces --if-present`：exit 0、0 错误。
- 全仓 `npm test`：exit 0，10 个 workspace 全绿（42/134/86/200/95/148+9skip/10/14/10/9）。
- `pi-image-gen` build + pack-smoke：exit 0；`pi-vendor` pack dry-run：exit 0。
- 新扩展隔离闸门：`pi-context-guard` typecheck 干净 + 9 测试通过；`pi-codemode-only` typecheck 干净 + 10 测试通过。

## 顺手发现
