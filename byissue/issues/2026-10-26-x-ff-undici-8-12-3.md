# pi-web-search 依赖审计：undici 8.11.2 → 8.12.3 并升 0.6.1

> 做了什么 · 改了哪些 · 怎么验证 · 对 `byissue/` 有无影响

三条 undici high advisory 覆盖 8.0.0–8.12.1，8.12.2 起修好：

- `GHSA-4qv8-2p9j-2685` EventSource 解析器内存无界（DoS）
- `GHSA-f72v-6w45-q472` SRI 算法 token 非小写导致完整性绕过
- `GHSA-xjj6-f33q-929c` 过多 content-encoding 未处理错误（DoS）

上次（issue 103）把 pin 停在 8.11.2，落在受影响区间内，因此再顺一版到 8.12.3。

## 改了哪些

- `packages/pi-web-search/package.json`：`dependencies.undici` `8.11.2` → `8.12.3`；`version` `0.6.0` → `0.6.1`。
- `package.json`：`overrides.undici` `8.11.2` → `8.12.3`。**这是 workspace 里真正生效的那一处**——只改包内 `dependencies` 会让 lockfile 里 root 仍解析到被 override 的旧版本（实测 `npm ls undici` 报 `invalid`，root `node_modules/undici` 停在 8.11.2）。两处必须同时改，与 issue 103 记录的结论一致。
- `package-lock.json`：`node_modules/undici` 8.12.3（新 integrity `sha512-+fdndUTwBP86...`），`packages/pi-web-search` 的 version 与依赖 pin 同步。
- 没有 `engines` 变更：8.12.3 的 `engines.node` 仍是 `>=22.19.0`，与 8.11.2 相同，包内 `engines` 维持 `>=20`（实际由根与 pi-coding-agent 的 Node 22 保证）。

### lockfile 落地的坑

`npm install` 直接跑只会多装一份 `packages/pi-web-search/node_modules/undici@8.12.3`，而 root 那份仍是 8.11.2（`npm ls` 报 `invalid`，因为 root override 与已安装版本不符）。正确顺序：

1. 改两处 pin；
2. `rm -rf node_modules/undici packages/pi-web-search/node_modules && npm install`（仍留下 root 8.11.2 + `peer: true` 标记的错位）；
3. `npm dedupe` —— 这一步才把 root 提到 8.12.3、消掉包内嵌套副本，lockfile 收敛成单条 `node_modules/undici`。

`npm dedupe` 还会顺手把 `@earendil-works/pi-coding-agent/node_modules/proper-lockfile/node_modules/retry` 合并上移到 `.../pi-coding-agent/node_modules/retry`。这是与 undici 无关的 lockfile 噪声，已手动回退该键名差异，最终 diff 只含 undici 与版本号，共 8 行。

## 怎么验证

- `npm audit` → undici 条目消失；剩 3 条与本次无关（`@vitest/mocker`/`vitest` 2 条 moderate、`vite` 1 条 high，均在 dev 树）。`npm audit --json` 里 `vulnerabilities.undici` 已不存在。
- `npm ci`（在 `/tmp` 干净副本上按 lockfile 全量重装）→ 退出 0，root `undici` 解析为 8.12.3，`npm ls undici --all` 三处全部 deduped 到 8.12.3，无 `invalid`。
- `npm run typecheck --workspaces --if-present` → 退出 0（六包 + 六个 small-extension 全过）。
- `npm test`（干净副本上与仓库内各跑一次）→ 退出 0，全绿。`pi-web-search` 16 passed / 1 skipped files，148 passed / 9 skipped tests。
- 重点回归：`html.test.ts`（`MockAgent` + 真 dispatcher 的 redirect/SSRF 用例）、`html-timeout.test.ts`、`html-fidelity.test.ts`、`spill-cleanup.test.ts`、`proxy.test.ts`（`getGlobalDispatcher`）全部通过，模块级 mock 的 `importOriginal` 形态未被破坏。
- 兼容性核对：8.11.2 → 8.12.3 的 `types/fetch.d.ts`、`mock-agent.d.ts`、`dispatcher.d.ts`、`env-http-proxy-agent.d.ts`、`proxy-agent.d.ts` 逐字节相同；`index.d.ts` 无差异。`src` 里的用法（`fetch` + `init.dispatcher` / `redirect: "manual"` / `signal`、`Agent`、`ProxyAgent`、`EnvHttpProxyAgent`、`MockAgent`）都在未变的类型面内，无需适配。
- `npm pack --workspace @bytetrue/pi-web-search --dry-run` → 16 文件、shasum `d619e98cbbde...`，包内 `package.json` 为 `0.6.1` + `undici 8.12.3`，零测试泄漏。
